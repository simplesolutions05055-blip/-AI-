## 2. שלב 5 — בדיקת CI שמונעת נסיגה ⬜

**למה זה הדבר החשוב ביותר שנשאר.** התיקונים של שלבים 1–4 הם חד־פעמיים. מה שיחזיר את המערכת אחורה זו הפונקציה ה־35 שתיכתב בעוד חודשיים בלי אימות — בדיוק כמו ש־`send-output` נכתבה.

**מה לבנות:** `scripts/check-function-auth.mjs`, שרץ ב־CI ונכשל אם פונקציה תחת `supabase/functions/` אינה עומדת באחד מאלה:

1. מכילה `requireUser`, `requireAdmin` או `denyUnauthenticated`
2. מאמתת סוד webhook: `CRON_SECRET`, `GROUP_WEBHOOK_SECRET`, או `validateSignature`
3. מופיעה ברשימת חריגים מפורשת **בתוך הסקריפט**, עם שורת הסבר

```js
// רשימת החריגים הנוכחית — כל תוספת חייבת נימוק
const PUBLIC_BY_DESIGN = {
  'request-password-reset': 'המשתמש לא מחובר בהגדרה; מוגן ב-codeSendThrottle',
  'send-gdpr-request':      '/data-requests ציבורי; 3 בקשות לשעה לכל IP',
  'signup':                 'הרשמה עצמית; אימות מייל',
  'resolve-invite':         'המוזמן טרם נרשם; מוגן בטוקן הזמנה',
  'meta-oauth-start':       'redirect בלבד לכתובת קבועה',
};
```

**נקודה עדינה:** הסקריפט צריך לזהות גם `verify_jwt = false` ב־`config.toml` ולדרוש שהפונקציה תופיע בחריגים או תאמת סוד. אחרת אפשר לכבות את השער בשקט.

**מאמץ:** חצי יום כולל חיווט ל־CI.

## 3. שלב 6 — להחזיר ל־RLS משמעות ⬜

**הבעיה המבנית:** `_shared/db.ts` מחזיר תמיד לקוח `service_role`, וכל הפונקציות משתמשות בו. כלומר **RLS עקוף תמיד בתוך Edge Function**. מסד הנתונים אינו קו הגנה שני — מה שהפונקציה מחליטה הוא סופי, וטעות אחת בבדיקת הרשאה היא גישה בלתי מוגבלת.

**הכיוון:**

```ts
// _shared/db.ts
export function dbAsUser(req: Request)  // לקוח עם ה-JWT של המשתמש; מכבד RLS
```

ואז, **פונקציה בכל פעם**, להעביר אליו קריאות שאין להן סיבה לעקוף RLS. `db()` נשאר רק ל:
- `auth.admin.*`
- כתיבה ל־`logs` ו־`rate_limit_events`
- מסלולי cron/webhook שאין מאחוריהם משתמש

**סדר מומלץ:** להתחיל מ־15 הפונקציות עם `getUser()` ידני — שם כבר יש JWT ביד, וההמרה היא בעיקר החלפת הלקוח. **לא** להתחיל מ־`process-request`/`worker.ts`; שם הפייפליין רץ גם ללא משתמש (וואטסאפ, cron) וההמרה מסובכת.

**מאמץ:** הדרגתי, בלי דדליין. כל פונקציה שמומרת היא רווח עצמאי.

15 פונקציות מימשו כל אחת בנפרד "מי קורא לי", עם וריאציות קטנות. עכשיו יש `_shared/auth.ts` שעושה את זה נכון במקום אחד.

זה **ניקיון, לא תיקון אבטחה** — כולן בודקות. הערך הוא שהבדיקה הבאה תהיה עקבית. כדאי לעשות את זה יחד עם שלב 6, באותה נגיעה בכל קובץ.

## 5. פריטים תפעוליים פתוחים — GREEN-API

### 5.1 להדליק את `stateWebhook` בקונסול ⬜ **פעולה שלך**

בקונסול של GREEN-API → Settings → **"Receive notifications about the instance authorization state change"**.

בלי זה עובד רק ה־polling כל 5 דקות (`conversation-maintenance`). עם זה — התראה מיידית. הקוד לשני המסלולים כבר קיים ופרוס.

### 5.2 מצב `suspended` ⬜ **דורש תשומת לב**

נכון ל־3 באוגוסט האינסטנס החזיר `suspended`. לפי התיעוד של GREEN-API זו **הגבלת שליחה בעקבות פעילות שזוהתה כספאם** — היורש של `yellowCard`. השלב הבא בסולם הוא `blocked`, כלומר חסימת המספר.

מה עוזר: להאט קצב שליחה, ולא לפנות למספרים שלא פנו אלינו ראשונים.

### 5.3 לשמור על הקישור חי ⬜ **פעולה ידנית, אין לה תחליף בקוד**

הטלפון הראשי חייב להתחבר לרשת **לפחות פעם ב-10 ימים**. WhatsApp מנתק מכשירים מקושרים אחרי ~14 יום בלי שהטלפון הראשי היה מקוון.

**לא לנסות לפתור את זה בקוד.** נבדק: שליחת הודעות תקופתית ("keepalive") לא שומרת על הקישור בכלל, ומוסיפה בדיוק את דפוס השליחה האוטומטית שיוצר `suspended`.

## 6. `twilio-webhook` — ✅ הוסר (4 באוגוסט 2026)

הראיות שהצדיקו את ההסרה:

| בדיקה | ממצא |
|---|---|
| הודעה אחרונה עם SID אמיתי של Twilio (`SM…`/`MM…`) | 12 ביולי 2026 |
| `twilio_bad_signature` אחרון בלוגים | 3 ביולי 2026 |
| קוד ששולח דרך Twilio | אין — אף אחד לא ייבא את `sendWhatsApp*` |

**המלכודת שכמעט הפילה את GREEN-API:** `_shared/greenapi.ts` ייבא את
`splitForWhatsApp` מ־`twilio.ts`, ו־`flow.ts`/`worker.ts` ייבאו משם את הטיפוס
`WhatsAppInteractive`. מחיקה ישירה של `twilio.ts` הייתה מפילה את כל ערוץ
הוואטסאפ. שני הפריטים האלה מעולם לא היו של Twilio — האחד הוא מגבלת אורך של
WhatsApp והשני טיפוס תצוגה.

**הסדר שבוצע — פירוק תלות, אימות, ורק אז מחיקה:**

1. נוצר `_shared/whatsappText.ts` עם `splitForWhatsApp` + הטיפוסים, **מועתקים
   מילה במילה** (אומת תכנותית שהקוד זהה בייט־בייט)
2. שלושת המייבאים הופנו לקובץ החדש
3. נפרס ו**אומת ש-GREEN-API עובד** — לפני שנמחק משהו
4. `supabase functions delete twilio-webhook` (מאומת: 404)
5. נמחקו `supabase/functions/twilio-webhook/` ו־`_shared/twilio.ts` והרישום ב־`config.toml`
6. נמחקו הסודות `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WEBHOOK_URL`, `TWILIO_WHATSAPP_FROM`
7. אומת שוב אחרי כל שלב

**אימות סופי:** ה־gateway נגיש, הגדרות ה־webhook תקינות, מנוע השיחה מגיב 200,
וה־cron של `conversation-maintenance` המשיך לתשאל את GREEN-API בהצלחה (0 כשלונות
אי פעם) — כלומר השרשרת `greenapi.ts → whatsappText.ts` רצה בפרודקשן, לא רק
מתקמפלת.

**נותר לך לוודא:** שאין webhook פעיל בקונסול של Twilio שמצביע לכתובת שנמחקה.
אין לי גישה לקונסול שלכם. גם אם יש — הוא רק יקבל 404 ולא ישבור שום דבר אצלנו.

**הערה:** המילה "Twilio" עדיין מופיעה בהערות היסטוריות בקוד ובשם העמודה
`messages.twilio_message_sid`. שינוי שם העמודה הוא מיגרציה שנוגעת בהרבה קוד —
לא שווה את הסיכון כרגע.
