# PrimeOS v2 - schema snapshot (23.10.2026)

Generated from the live database. The source of truth is the database; migrations are applied through the Supabase API and listed in the dashboard (Database -> Migrations). This file is the readable copy kept with the code.

All access goes through the Edge Functions (service role). RLS is enabled on every v2 table with no policies, so the public API (anon / authenticated) cannot read them at all.

## Tables

| table | purpose | key columns |
|---|---|---|
| organizations | a client (municipality / organisation) | id, name, plan (basic/extended), status, quotas jsonb, settings jsonb (agreement, depts, main_dept), contact_*, contact_phone_key (generated) |
| org_members | users of a client | id, org_id, name, email, phone, phone_key (generated), role (owner/admin/member), view (ext/dept), dept, perms jsonb {direct} |
| org_state | the client's app state as one JSON (brand, channels, campaigns, events, member slices) | org_id, data, updated_at |
| content_items | the content library; `meta.ui` is the item as the app holds it | id, org_id, ui_id (app id), type, status, scheduled_for, meta, updated_at |
| api_tokens | client tokens: internal (bot / server) and session (browser, expires) | token (pk), org_id, member_id, kind, expires_at |
| admin_users / admin_tokens / admin_state | the management console: admins, their sessions, console state (vendors, prices, pub provider, monitor) | - |
| v2_login_codes | one-time codes and entry links | email, kind, purpose (code/direct/enter/invite), code_hash, link_hash, expires_at, used_at |
| v2_jobs | server jobs (graphics / videos made by the bot or the runner) | org_id, member_id, phone, kind, step, state (run/await/done/error), input, data, pend, next_at, lock_until, ui_id |
| v2_usage | every AI / media call with its units (tokens, images by quality, tts chars, music sec, render sec) | org_id, member_id, kind, model, created_at |
| v2_pub_posts / v2_pub_profiles / v2_pub_events | publishing through the provider (Zernio): posts sent, connected accounts, webhook ids seen | org_id, ui_id, provider, post_id, status |
| v2_wa_sessions / v2_wa_msgs / v2_wa_raw | WhatsApp bot: conversation state per phone, every message in and out (dir in/out/err), raw provider payloads (3 days) | phone, org_id, state / body / body |
| v2_brand_kits | the graphic language read from a logo, cached per org + logo | org_id, logo, kit |
| v2_audit | management actions: who did what to whom, from where | org_id, actor_kind, actor_id, action, target, ip, created_at |
| v2_secrets | server-side secrets kept in the database (tick key, inbound WhatsApp key) | k, v |

## Indexes that matter
content_items (org_id, ui_id), (org_id, updated_at desc), (org_id, status), (org_id, scheduled_for); org_members (phone_key); organizations (contact_phone_key); v2_jobs (state, next_at), (org_id, created_at); v2_usage (org_id, created_at); v2_wa_msgs (phone, created_at); v2_audit (org_id, created_at), (created_at).

## Functions and schedules (pg_cron)
- v2_jobs_tick(): every minute, pokes the job runner when jobs are waiting; sweeps v2_wa_raw older than 3 days.
- v2_monitor_tick(mode): run every 5 minutes (health checks + alerts), backup weekly Sunday 01:00 UTC, tenant daily 02:30 UTC (isolation test).
- v2_phone_key(text): phone normalisation for the generated columns.
- v2_http(): a pg_net POST with headers, used by the job runner for long provider calls.

## Storage buckets
- v2-content (public): client uploads `up/<org>/`, generated media `ai/<org>/`, renders.
- v2-backups (private): weekly JSON copy of every table above, one folder per date, 8 weeks kept.
